How tasks are labeled

Capability labels describe visible features of a repair.

Automatic labeling

Rules inspect changed file paths and added code in the reference repair and its tests. A task can receive several labels. Source changes commonly receive the implementation label, and test changes receive the testing label.

These labels are a practical description of the change. They do not establish that a task isolates one skill or that every labeled skill was necessary to solve it.

Labels and performance

A label identifies a category; a category success rate summarizes evaluated outcomes. A formal category ranking requires additional evidence that enough relevant tests and tasks have been checked. Those checks are incomplete for the current catalogue, so descriptive rates should not be read as certified capability rankings.

Read coverage carefully

The quality report shows all categories, including those with no covered tasks. A task can appear in more than one category, so totals overlap.

A label marked declared has not been independently re-derived from the full repair. This is common for live tasks, whose reference patches remain withheld. A missing performance estimate is different from a measured zero success rate.
