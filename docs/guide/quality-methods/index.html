Selection-quality methods (MSQ)

Multi-angle Selection-Quality — how well a task set discriminates models.

Scored from a graded (task × model) matrix.

Scope and limits

Module
terminal_daily_bench.quality
Pure
Pure functions over plain lists; they neither read nor change reward decisions.
Blind to
Semantic verifier false-accept — MSQ cannot measure it.
Deterministic
Randomized routines are seeded; a resume reproduces the interval.
Advisory
No MSQ number and no readiness verdict ever gates an accept.
Undefined
An axis without a population returns None, never a fabricated number.

The matrix convention

Solved means grade >= solved_threshold (default 1). Binary 0/1 and graded 0..K both work, and the CLI builds the matrix for you (below).

matrix   rows = tasks, cols = models
         matrix[t][j] = the graded outcome of model j on task t (int, 0 = fail)

What enters the matrix

A run produces a status before it produces a grade. Only an authenticated SUCCESS with score_accepted=true becomes a numeric outcome; SUCCESS with score_accepted=false, FAILED, BLOCKED and NOT_RUN all record outcome:null. All five statuses are counted in coverage.

Null is not zero. Those rows are not converted to zero and are excluded from ratings, because a task that could not be attempted is not a task the model failed — zeroing them would move a harness outage into the model’s score. They are counted in coverage, not outcomes, so a model that ran few tasks shows low coverage rather than a clean-looking rate.

Two tallies, never summed

A declaration cannot authenticate its own status, so the two tallies are never summed.

authenticated_counts
Bound to receipts.
untrusted_declared_counts
Bound to what a submission asserted about itself.

Which dimensions may be ranked

Three dimensions, each bound by the trusted task catalogue. ALLOWED_DIMENSIONS enforces the list in code, and a dimension outside it is not rendered. Unavailable and zero are different claims.

overall
Rankable.
language
Rankable.
capability
Authorised. The C1–C14 labels are published on every archive package, but no axis clears the publish gate on this catalogue.
task-family
Task-family: unavailable. Historical data carries no authority-bound family field. The site does not infer one from tracks, merged labels, or repository metadata, and does not display zero.

Separate estimands

Model, harness, and complete-configuration effects stay separate estimands: a harness effect is never read as a model effect, and a configuration score is never relabelled as model-only performance.

What triggers a label

A changed path matches a path rule
Tags that rule’s code, once per matching path.
A token rule matches the diff
Tags that rule’s code. Added lines only, word-boundary matched — a deleted line or a diff header never tags a task.
The test diff is non-empty
Always adds C5; the test diff is what carries the verifiable signal.
A changed non-test source file
Always adds C4.
Nothing matched
Defaults to C3. The label list is never empty.
Order
Hit count descending, then code number. The list is a total order, not a set.

The two unconditional rules are why C5 and C4 sit on nearly every archive package. Per-axis coverage and gate status on today’s catalogue is on the capability coverage report; a defined label set is not a scoreable axis, and that page says which axes clear the gate.

The measurement axes

Each axis is [0, 1], higher = better, and every one is reported separately so the composite never hides a collapsed axis.

D — discriminative yield

The fraction of tasks that split the field: only tasks some models solve and others miss carry information, and the rest are the blind spot.

D = |{ tasks with 0 < solvers < n_models }| / n_tasks

An all-pass or all-fail task therefore carries zero discrimination. With fewer than two models D is None. Its default composite weight is 0.5.

C — difficulty coverage

Normalized entropy of solve-rate bucket occupancy, over equal-width bins on [0, 1].

C = ( -Σ p_b · log p_b ) / log(n_buckets)      p_b = fraction of tasks in bucket b

Tasks spread evenly give C = 1; tasks all clustered in one bucket give C = 0.

M — monotonicity

The fraction of tasks with no strong ability inversion.

M = |{ monotonic tasks }| / n_tasks
Compared pairs
Those where ability_i > ability_j + ability_eps, with ability_eps defaulting to 0.05.
Strong inversion
solved_j and not solved_i — noise, mislabel, or gameability.
Monotonic task
One with zero inversions.
Ability
Defaults to each model’s overall solve-rate; with no ability separation M is vacuously 1.0.

A — angle coverage

capability_profile decomposes the gate-states 0..4 into four conditional rates:

build_rate
Can produce a building env — P(state ≥ 1).
partial_given_build
Can start fixing, some F2P — P(state ≥ 2 | ≥ 1).
full_f2p_given_partial
Can complete the F2P fix — P(state ≥ 3 | ≥ 2).
clean_given_full_f2p
Can fix without breaking P2P — P(state = 4 | ≥ 3).

angle_coverage(graded, min_support=3) reports, per angle, the support (size of the conditioning population), whether it is covered (support ≥ min_support), the uncovered_angles that fall short, and all_covered. An empty conditioning population returns None, never a fabricated number, so a set that never reaches stage ≥ 3 cannot measure clean_given_full_f2p. The whole axis is advisory.

R — diversity

R scores task signatures ({repo, files, f2p}), not the response matrix.

task_similarity(a, b)
0.0 for different repos (definitionally diverse); for the same repo, the mean of the changed-file Jaccard and the F2P-selector Jaccard.
redundancy_rate(sigs, threshold=0.6)
The fraction of tasks with at least one near-duplicate.
diversity
1 − redundancy_rate, and None below two tasks.
signature_of(task)
A best-effort duck-typed signature from a task object.

I — IRT test information

irt_item_stats fits the binary matrix to the 2-parameter logistic model, and information is additive across items (conditionally independent), so it sums over the test.

I_item(theta) = a² · P · (1 − P)        P = 1 / (1 + e^{−a(theta − b)})
I_test(theta) = Σ_items a² · P · (1 − P)          SE(theta) = 1 / √I_test
b — difficulty
logit(1 − solve_rate); harder tasks (low solve-rate) get higher b.
a — discrimination
max(0.2, |r_pb|·2 + 0.2), where r_pb is the task’s point-biserial correlation with the per-model total score. An all-pass, all-fail or non-correlating item floors to a small a — it discriminates nothing.
select_max_information
The max-information subset is exactly the top-k items, so there is no greedy pass.
information_se(info)
That SE; ∞ with no information.

KR-20 — reliability

Kuder-Richardson 20 — internal-consistency reliability for binary items.

KR20 = ( k / (k−1) ) · ( 1 − Σ p_i·q_i / σ²_total )
k, p_i, q_i, σ²_total
Tasks; the pass rate of task i; 1 − p_i; the per-model total-score variance.
Undefined
None when k < 2, or when that variance is 0.
Rule of thumb
> 0.7 acceptable, > 0.8 good; a negative value means the items are mutually inconsistent.

Bootstrap confidence intervals

msq_bootstrap_ci resamples the task rows with replacement, n_boot times, recomputing D/C/M on each resample.

{ estimate, lo, hi, se, n_valid }

estimate is the full-set point estimate, [lo, hi] the central ci-percentile interval (default 95%), and se the bootstrap SD. The RNG is seeded, so a resume is reproducible. At N ≈ 6 tasks the intervals are wide.

Precision-power (required-N)

required_tasks_for_precision scales SE as 1/√N from the bootstrap SE at N₀.

half_width h(N) = z · SE(N₀) · √(N₀ / N)
required N       = N₀ · ( z · SE(N₀) / target_half_width )²      (rounded up)

It returns one record per axis — {axis, n_now, se_now, half_width_now, target_half_width, required_n} — where required_n is None when the axis SE is undefined and 0 when SE is already 0. precision_curve(matrix, sizes, axis="D") gives the curve [{n, half_width}, ...].

Reliability-power (required-N)

tasks_for_reliability applies the Spearman-Brown prophecy to give the test length needed to reach a target KR-20.

k' = k · [ ρ'·(1 − ρ) ] / [ ρ·(1 − ρ') ]        (rounded up, floored at 1)

It returns {current_kr20, current_k, target_kr20, required_k} measured from the current KR-20, with required_k None when reliability is undefined or ≤ 0, or the target is outside (0, 1).

The readiness verdict

benchmark_readiness folds discrimination, reliability and precision into one daily GO/NO-GO advisory. It is ready iff all three hold:

D ≥ min_D            (default 0.4)
KR-20 ≥ min_kr20     (default 0.7)
D 95%-CI half-width ≤ max_d_halfwidth   (default 0.15)
reasons
Each failing constraint with its value, threshold and required_n. A None on any axis fails that axis.
bottleneck
The failing constraint that demands the most tasks.
recommended_n
max(precision-required-N, reliability-required-N).
status
Advisory only: it never gates an accept.

What the card does not license

A ranking is not a result.
At this N one model’s Wilson interval covers most of the others.
D is coarse at small N.
One task flipping moves it a step.
Not yet one instrument.
Below the KR-20 bar the total is not a skill estimate.
A vacuous high is not a win.
M reaches 1.0 when no separation is left to violate.
Required-N is an order of magnitude.
It assumes the next tasks are drawn like today’s; it is today’s bootstrap SE extrapolated at 1/√N.
Readiness is advisory.
It never gates an accept or touches the reward path.

What it does catch is a collapsed set: all-pass or all-fail rows, a negatively correlating item, a missing difficulty band.

Reading the discrimination report

These notes are standing methodology for the selection-quality report, so they live here rather than beside every figure.

Provisional readings
Provisional readings, not properties — every number on that page is recomputed from the published matrix at page load.
Scaffold scope
The solve matrix is one scaffold, one model family, one day. It is never the whole model suite, and its cells are not independent trials.
Hollow squares
A hollow square is a task from another suite, not a skipped run. Where a run really was skipped under the reported scaffold, the note on the figure says so instead and names the count.
Overlapping intervals
Overlapping Wilson intervals are not a significance test. Where a figure paints a shaded band, that band marks the range every count in that group still allows.
The level rows
The difficulty rows are a partition of the publication-mode row above them, not peer groups. They are compared inside one publication mode only: pooling the modes puts structurally-zero tasks into the comparison and the result is an artifact of pooling.
Publication mode
Live vs archive is a difference in what is withheld, not measured difficulty. Live withholds gold patches, protected test bodies and merge provenance; archive publishes them. Harder, newer and measured differently cannot be told apart. Any other publication mode likewise differs in what the task package publishes, so those rows are coverage facts, not difficulty findings.
Declared difficulty
Declared difficulty is editorial — the task.toml label, never measured.
Authority
Nothing on that page is ranked or certified: no publication bundle is approved, no matrix digest is trusted, and receipt authority is inactive — which is why the registry’s Official solves column is a dash.

Reading the capability coverage report

Every axis is listed
All fourteen axes are listed. An axis this catalogue does not cover is a fact about the catalogue, not a row to hide — so an axis carrying no task at all is listed at zero rather than dropped: a missing row reads as an axis that does not exist, which is a different claim from an axis this catalogue never reached.
The co-occurrence grid
One column per re-derivable package, one row per axis; a mark is presence, never a degree. No model outcome is in that figure — it is not a solve result. Columns are ordered by how many labels a package carries, so the dense left edge is arrangement, not a finding.
Multi-valued labels
A task carries every code its diff triggers, so the per-code counts do not sum to the task count.
The unmeasured criterion
min_admitted_subtests counts the subtests surviving a unit-test-validity audit, and no such audit has classified this catalogue. Unmeasured is not failed, and it is certainly not passed — so no axis clears the publish gate whatever its counts say.
The audit on record
The unit-test-validity audit on record does not describe this catalogue (release b3fc3e6, experiments/reports/unit-test-validity-r001/SUMMARY.json). It measured a different corpus at a different release commit; its per-axis counts describe that corpus, so they are not reproduced on the report and min_admitted_subtests stays unmeasured here.
Packages that cannot be tagged
The tagger reads the oracle diff and live withholds it, so a live package’s task.toml keywords stand as declared, never re-derived — and every count on the report is over the packages that could be checked.

One-call quality card

benchmark_quality_report(matrix, ..., deep=True) aggregates every axis: msq (the D/C/M profile plus composite), diversity from signatures, angle coverage from the flat graded states, noisy_task_indices (monotonicity violations), and a curated subset (monotonic core → info-max → diverse filter). Under deep=True it adds IRT (total_information + SE), ci bootstrap intervals, power precision required-N, reliability KR-20, and reliability_prophecy Spearman-Brown required-k.

from terminal_daily_bench import quality as q

matrix = [
    [1, 0, 0],   # td-1: A solves, B/C fail  -> splits
    [1, 1, 0],   # td-2
    [1, 1, 1],   # td-3: all-pass            -> no discrimination
    [0, 0, 0],   # td-4: all-fail            -> no discrimination
    [1, 0, 1],   # td-5
    [1, 1, 0],   # td-6
]

card = q.benchmark_quality_report(matrix, deep=True)
print(card["msq"])          # {'D': 0.667, 'C': 0.896, 'M': 0.833, 'composite': 0.766, ...}
print(card["irt"]["total_information"])   # 1.808
print(card["reliability"]["kr20"])        # 0.514

verdict = q.benchmark_readiness(matrix)
print(verdict["ready"], verdict["bottleneck"], verdict["recommended_n"])
# False precision 37

How tdb quality surfaces it

It reads a results file — JSONL or a JSON list — builds the matrix, prints the quality card and then the readiness line. Each record needs task, model, and either solved or reward; solved is taken as reward ≥ 0.999, rows with model == "oracle" are excluded, and the command exits 2 below ≥ 1 task and ≥ 2 models.

# results.jsonl — one record per (model, task) run, exactly as `tdb run` emits
# {"task":"td-1","model":"A","reward":1.0}
# {"task":"td-1","model":"B","reward":0.0}
# ...
