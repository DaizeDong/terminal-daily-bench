selection-quality methods (MSQ)

Multi-angle Selection-Quality — how well a task set discriminates models.

Scored from a graded (task × model) matrix.

Scope and limits

propertywhat it means
moduleterminal_daily_bench.quality
purepure functions over plain lists; they neither read nor change reward decisions
blind tosemantic verifier false-accept — MSQ cannot measure it
deterministicrandomized routines are seeded; a resume reproduces the interval
advisoryno MSQ number and no readiness verdict ever gates an accept
undefinedan axis without a population returns None, never a fabricated number

The matrix convention

matrix   rows = tasks, cols = models
         matrix[t][j] = the graded outcome of model j on task t (int, 0 = fail)

Solved means grade >= solved_threshold (default 1).

Binary 0/1 and graded 0..K both work.

The CLI builds the matrix for you (below).

What enters the matrix

A run produces a status before it produces a grade.

Only an authenticated SUCCESS with score_accepted=true becomes a numeric outcome.

FAILEDoutcome:nullcounted
BLOCKEDoutcome:nullcounted

Null is not zero

D — discriminative yield

The fraction of tasks that split the field.

D = |{ tasks with 0 < solvers < n_models }| / n_tasks
caseresult
all-pass or all-fail taskcarries zero discrimination
fewer than 2 modelsNone
default composite weight0.5

C — difficulty coverage

Normalized entropy of solve-rate bucket occupancy.

C = ( -Σ p_b · log p_b ) / log(n_buckets)      p_b = fraction of tasks in bucket b
caseresult
n_bucketsequal-width bins on [0, 1]
tasks spread evenlyC = 1
tasks all cluster in one bucketC = 0

M — monotonicity

Fraction of tasks with no strong ability inversion.

M = |{ monotonic tasks }| / n_tasks
termdefinition
compared pairsthose where ability_i > ability_j + ability_eps
ability_epsdefault 0.05
strong inversionsolved_j and not solved_i — noise, mislabel, or gameability
monotonic taskiff zero inversions
abilitydefaults to each model’s overall solve-rate
no ability separationM is vacuously 1.0

A — angle coverage

capability_profile decomposes the gate-states 0..4 into four conditional rates:

anglemeaningconditions on state ≥
build_rate can produce a building env — P(state ≥ 1) 0
partial_given_build can start fixing (some F2P) — P(state ≥ 2 | ≥ 1) 1
full_f2p_given_partial can complete the F2P fix — P(state ≥ 3 | ≥ 2) 2
clean_given_full_f2p can fix without breaking P2P — P(state = 4 | ≥ 3) 3

angle_coverage(graded, min_support=3) reports, per angle:

I — IRT test information

irt_item_stats fits the binary matrix to the 2-parameter logistic model.

item parameterestimate
b — difficultylogit(1 − solve_rate); harder tasks (low solve-rate) get higher b
a — discriminationmax(0.2, |r_pb|·2 + 0.2), where r_pb is the task’s point-biserial correlation with the per-model total score
all-pass / all-fail / non-correlating itemfloors to a small a — it discriminates nothing

Each item’s Fisher information at ability theta:

I_item(theta) = a² · P · (1 − P)        P = 1 / (1 + e^{−a(theta − b)})

Information is additive (items conditionally independent), so it sums over the test:

I_test(theta) = Σ_items a² · P · (1 − P)          SE(theta) = 1 / √I_test
callreturns
select_max_informationthe max-information subset is exactly the top-k items, so there is no greedy pass
information_se(info)that SE; ∞ with no information

KR-20 — reliability

Kuder-Richardson 20 — internal-consistency reliability for binary items:

KR20 = ( k / (k−1) ) · ( 1 − Σ p_i·q_i / σ²_total )
termmeaning
ktasks
p_ipass rate of task i
q_i1 − p_i
σ²_totalper-model total-score variance
k < 2, or that variance is 0None
rule of thumb> 0.7 acceptable, > 0.8 good
negativeitems are mutually inconsistent

Uncertainty and power

Bootstrap confidence intervals

msq_bootstrap_ci resamples the task rows with replacement, n_boot times.

Each resample recomputes D/C/M.

{ estimate, lo, hi, se, n_valid }
fieldmeaning
estimatethe full-set point estimate
[lo, hi]the central ci-percentile interval (default 95%)
sethe bootstrap SD
RNGseeded → resume-reproducible
at N ≈ 6 tasksintervals are wide

Precision-power (required-N)

required_tasks_for_precision scales SE as 1/√N from the bootstrap SE at N₀:

half_width h(N) = z · SE(N₀) · √(N₀ / N)
required N       = N₀ · ( z · SE(N₀) / target_half_width )²      (rounded up)
returnsnotes
{axis, n_now, se_now, half_width_now, target_half_width, required_n}one record per axis
required_n is Nonewhen the axis SE is undefined
required_n is 0when SE is already 0
precision_curve(matrix, sizes, axis="D")the curve [{n, half_width}, ...]

Reliability-power (required-N)

tasks_for_reliability applies the Spearman-Brown prophecy.

It gives the test length needed to reach a target KR-20:

k' = k · [ ρ'·(1 − ρ) ] / [ ρ·(1 − ρ') ]        (rounded up, floored at 1)
returnsnotes
{current_kr20, current_k, target_kr20, required_k}measured from the current KR-20
required_k is Nonewhen reliability is undefined or ≤ 0, or the target is outside (0, 1)

The readiness verdict

benchmark_readiness folds discrimination, reliability, and precision together.

One daily GO/NO-GO advisory.

ready iff all three hold:

D ≥ min_D            (default 0.4)
KR-20 ≥ min_kr20     (default 0.7)
D 95%-CI half-width ≤ max_d_halfwidth   (default 0.15)

What a NO-GO reports

fieldcontents
reasonseach failing constraint with value, threshold, required_n
bottleneckthe failing constraint that demands the most tasks
recommended_nmax(precision-required-N, reliability-required-N)
a None on any axisfails that axis
statusadvisory only: never gates an accept

One-call quality card

benchmark_quality_report(matrix, ..., deep=True) aggregates every axis.

keycontentsneeds
msqthe MSQ profile: D/C/M + composite
diversityfrom signatures
angle coveragefrom flat graded states
noisy_task_indicesmonotonicity violations
curated subsetmonotonic core → info-max → diverse filter
IRTtotal_information + SEdeep=True
cibootstrap intervalsdeep=True
powerprecision required-Ndeep=True
reliabilityKR-20deep=True
reliability_prophecySpearman-Brown required-kdeep=True
 
from terminal_daily_bench import quality as q

matrix = [
    [1, 0, 0],   # td-1: A solves, B/C fail  -> splits
    [1, 1, 0],   # td-2
    [1, 1, 1],   # td-3: all-pass            -> no discrimination
    [0, 0, 0],   # td-4: all-fail            -> no discrimination
    [1, 0, 1],   # td-5
    [1, 1, 0],   # td-6
]

card = q.benchmark_quality_report(matrix, deep=True)
print(card["msq"])          # {'D': 0.667, 'C': 0.896, 'M': 0.833, 'composite': 0.766, ...}
print(card["irt"]["total_information"])   # 1.808
print(card["reliability"]["kr20"])        # 0.514

verdict = q.benchmark_readiness(matrix)
print(verdict["ready"], verdict["bottleneck"], verdict["recommended_n"])
# False precision 37

Prints the quality card, then the readiness line.
