selection-quality methods (MSQ)

terminal_daily_bench.quality scores Multi-angle Selection-Quality (MSQ): how well a task set discriminates models, from a graded (task × model) matrix.

Pure functions over plain lists: they neither read nor change reward decisions, and cannot measure semantic verifier false-accept. Randomized routines are seeded and deterministic; a resume reproduces the interval.

The matrix convention

matrix   rows = tasks, cols = models
         matrix[t][j] = the graded outcome of model j on task t (int, 0 = fail)

Solved means grade >= solved_threshold (default 1); binary 0/1 and graded 0..K both work. The CLI builds it from a results file (below).

What enters the matrix

A run produces a status before it produces a grade. Only an authenticated SUCCESS with score_accepted=true becomes a numeric outcome.

Execution status Outcome Coverage
SUCCESS, score_accepted=truegradedcounted
SUCCESS, score_accepted=falseoutcome:nullcounted
FAILEDoutcome:nullcounted
BLOCKEDoutcome:nullcounted
NOT_RUNoutcome:nullcounted

The rows that use outcome:null are not converted to zero and are excluded from ratings. A task that could not be attempted is not a task the model failed; converting it would move a harness outage into the model’s score. They are counted in coverage, not outcomes, so a model that ran few tasks shows low coverage rather than a clean-looking rate.

Statuses are tallied twice. authenticated_counts are receipt-bound; untrusted_declared_counts are what a submission asserted about itself. A declaration cannot authenticate its own status, so the two are never summed.

Which dimensions may be ranked

Three: overall, language, and the canonical C1–C14 capability labels bound by the trusted task catalogue. The leaderboard enforces this list in code (ALLOWED_DIMENSIONS); a dimension outside it is not rendered, however complete the data looks.

Task-family: unavailable. Historical data carries no authority-bound family field. The site does not infer one from tracks, merged labels, or repository metadata, and does not display zero — unavailable and zero are different claims.

Model, harness, and complete-configuration effects stay separate estimands. A configuration score is never relabelled as model-only performance.

The measurement axes

Each axis is [0, 1], higher = better, reported separately: the composite never hides a collapsed axis.

D — discriminative yield · discriminative_yield

The fraction of tasks that split the field; all-pass and all-fail tasks carry zero discrimination.

D = |{ tasks with 0 < solvers < n_models }| / n_tasks

Returns None with fewer than 2 models. Default composite weight 0.5.

C — difficulty coverage · difficulty_coverage

Normalized entropy of solve-rate bucket occupancy over n_buckets equal-width bins on [0, 1]: 1 when tasks spread evenly, 0 when they all cluster in one bucket.

C = ( -Σ p_b · log p_b ) / log(n_buckets)      p_b = fraction of tasks in bucket b

M — monotonicity · monotonicity

Fraction of tasks with no strong ability inversion: over pairs where ability_i > ability_j + ability_eps (default eps = 0.05), a strong inversion is solved_j and not solved_i — noise, mislabel, or gameability. Monotonic iff zero inversions.

M = |{ monotonic tasks }| / n_tasks

Ability defaults to each model's overall solve-rate; with no ability separation, M is vacuously 1.0.

A — angle coverage · angle_coverage

From the ordinal gate-states 0..4, capability_profile decomposes ability into four conditional rates, each conditioned on the previous stage:

anglemeaningconditions on state ≥
build_rate can produce a building env — P(state ≥ 1) 0
partial_given_build can start fixing (some F2P) — P(state ≥ 2 | ≥ 1) 1
full_f2p_given_partial can complete the F2P fix — P(state ≥ 3 | ≥ 2) 2
clean_given_full_f2p can fix without breaking P2P — P(state = 4 | ≥ 3) 3

An empty conditioning population gives None, never a fabricated number. angle_coverage(graded, min_support=3) reports per angle: support, covered (support ≥ min_support), uncovered_angles, all_covered. A set never reaching stage ≥ 3 cannot measure clean_given_full_f2p. Advisory only.

R — diversity / anti-redundancy · diversity

R scores task signatures ({repo, files, f2p}), not the response matrix:

  • task_similarity(a, b) → 0.0 for different repos (definitionally diverse); for the same repo, the mean of the changed-file Jaccard and the F2P -selector Jaccard.
  • redundancy_rate(sigs, threshold=0.6) → fraction of tasks with ≥ 1 near-duplicate.
  • diversity = 1 − redundancy_rate.

signature_of(task) best-effort duck-types a signature from a task object; None for fewer than 2 tasks.

I — IRT (2PL) test information · total_information_2pl

irt_item_stats fits the binary matrix to the 2-parameter logistic model, giving each task an a (discrimination) and b (difficulty):

  • b = logit(1 − solve_rate) — harder tasks (low solve-rate) get higher b.
  • a = max(0.2, |r_pb|·2 + 0.2) where r_pb is the task's point-biserial correlation with the per-model total score. An all-pass / all-fail / non-correlating item floors to a small a — it discriminates nothing.

Each item's Fisher information at ability theta:

I_item(theta) = a² · P · (1 − P)        P = 1 / (1 + e^{−a(theta − b)})

Item information is additive (items conditionally independent), so the max-information subset is exactly the top-k items (select_max_information, no greedy pass):

I_test(theta) = Σ_items a² · P · (1 − P)          SE(theta) = 1 / √I_test

information_se(info) returns that SE (∞ with no information).

KR-20 — reliability · reliability_kr20

Internal-consistency reliability — Kuder-Richardson 20, for binary items:

KR20 = ( k / (k−1) ) · ( 1 − Σ p_i·q_i / σ²_total )

k = tasks, p_i = pass rate of task i, q_i = 1 − p_i, σ²_total = per-model total-score variance. None when k < 2 or that variance is 0. Rule of thumb: > 0.7 acceptable, > 0.8 good; negative when items are mutually inconsistent.

Uncertainty and power

Bootstrap confidence intervals · msq_bootstrap_ci

Resamples the task rows with replacement n_boot times (seeded RNG → resume-reproducible), recomputing D/C/M. Per axis:

{ estimate, lo, hi, se, n_valid }

estimate is the full-set point estimate, [lo, hi] the central ci-percentile interval (default 95%), se the bootstrap SD. At N ≈ 6 tasks intervals are wide.

Precision-power (required-N) · required_tasks_for_precision

SE scales as 1/√N from the bootstrap SE at N₀:

half_width h(N) = z · SE(N₀) · √(N₀ / N)
required N       = N₀ · ( z · SE(N₀) / target_half_width )²      (rounded up)

Returns {axis, n_now, se_now, half_width_now, target_half_width, required_n}; required_n is None when the axis SE is undefined, 0 when SE is already 0. precision_curve(matrix, sizes, axis="D") gives the curve [{n, half_width}, ...].

Reliability-power (required-N) · tasks_for_reliability

Spearman-Brown prophecy: the test length needed to reach a target KR-20 from the current one:

k' = k · [ ρ'·(1 − ρ) ] / [ ρ·(1 − ρ') ]        (rounded up, floored at 1)

Returns {current_kr20, current_k, target_kr20, required_k}. required_k is None when reliability is undefined or ≤ 0, or the target is outside (0, 1).

The readiness verdict · benchmark_readiness

Discrimination, reliability, and precision fold into one daily GO/NO-GO advisory naming the binding bottleneck. ready iff all three hold:

D ≥ min_D            (default 0.4)
KR-20 ≥ min_kr20     (default 0.7)
D 95%-CI half-width ≤ max_d_halfwidth   (default 0.15)

A None on any axis fails it. On NO-GO, reasons lists each failing constraint with value, threshold, required_n; bottleneck demands the most tasks; recommended_n = max(precision-required-N, reliability-required-N). Advisory only: never gates an accept.

One-call quality card · benchmark_quality_report

benchmark_quality_report(matrix, ..., deep=True) aggregates every axis: the MSQ profile (D/C/M + composite), diversity (from signatures), angle coverage (from flat graded states), noisy_task_indices (monotonicity violations), a curated subset (monotonic core → info-max → diverse filter). deep=True adds IRT total_information + SE, bootstrap ci, precision power, reliability (KR-20), reliability_prophecy.

from terminal_daily_bench import quality as q

matrix = [
    [1, 0, 0],   # td-1: A solves, B/C fail  -> splits
    [1, 1, 0],   # td-2
    [1, 1, 1],   # td-3: all-pass            -> no discrimination
    [0, 0, 0],   # td-4: all-fail            -> no discrimination
    [1, 0, 1],   # td-5
    [1, 1, 0],   # td-6
]

card = q.benchmark_quality_report(matrix, deep=True)
print(card["msq"])          # {'D': 0.667, 'C': 0.896, 'M': 0.833, 'composite': 0.766, ...}
print(card["irt"]["total_information"])   # 1.808
print(card["reliability"]["kr20"])        # 0.514

verdict = q.benchmark_readiness(matrix)
print(verdict["ready"], verdict["bottleneck"], verdict["recommended_n"])
# False precision 37

Selection helpers: select_informative_subset (greedy D + C), select_max_information (top-k Fisher), balanced_subset (difficulty-balanced), diverse_subset (farthest-point over signatures), select_mid_difficulty (scaffold-relative discriminative band), filter_monotonic / flag_noisy_tasks (drop ability-inverting tasks), cross_scaffold_quality (most discriminative scaffold frame).

How tdb quality surfaces it

Reads a results file (JSONL or a JSON list), builds the (task × model) matrix, prints the card and readiness line. Records need task, model, and either solved or reward (solved when reward ≥ 0.999); model == "oracle" rows are excluded.

# results.jsonl — one record per (model, task) run, exactly as `tdb run` emits
# {"task":"td-1","model":"A","reward":1.0}
# {"task":"td-1","model":"B","reward":0.0}
# ...

tdb quality results.jsonl

Output on the 6-task / 3-model example above:

tasks=6 models=3
  D(discrimination)=0.667  C(coverage)=0.896  M(monotonicity)=0.833
  IRT test-information=1.808  KR-20 reliability=0.5142857142857141
  D 95% CI=[0.333, 1.000]
  readiness: NOT-ready (bottleneck=precision, need ~37 tasks)
{"msq": {...}, "irt": {...}, "reliability": {...}, "readiness": {...}}

The last line is that card as JSON. tdb quality requires ≥ 1 task and ≥ 2 models; exits 2 otherwise.
