selection-quality methods (MSQ)

Multi-angle Selection-Quality — how well a task set discriminates models.

Scored from a graded (task × model) matrix.

Scope and limits

propertywhat it means
moduleterminal_daily_bench.quality
purepure functions over plain lists; they neither read nor change reward decisions
blind tosemantic verifier false-accept — MSQ cannot measure it
deterministicrandomized routines are seeded; a resume reproduces the interval
advisoryno MSQ number and no readiness verdict ever gates an accept
undefinedan axis without a population returns None, never a fabricated number

The matrix convention

matrix   rows = tasks, cols = models
         matrix[t][j] = the graded outcome of model j on task t (int, 0 = fail)

Solved means grade >= solved_threshold (default 1).

Binary 0/1 and graded 0..K both work.

The CLI builds the matrix for you (below).

What enters the matrix

A run produces a status before it produces a grade.

Only an authenticated SUCCESS with score_accepted=true becomes a numeric outcome.

Null is not zero

D — discriminative yield

The fraction of tasks that split the field.

Only tasks some models solve and others miss carry information; the rest are the blind spot.

D = |{ tasks with 0 < solvers < n_models }| / n_tasks
caseresult
all-pass or all-fail taskcarries zero discrimination
fewer than 2 modelsNone
default composite weight0.5

C — difficulty coverage

Normalized entropy of solve-rate bucket occupancy.

C = ( -Σ p_b · log p_b ) / log(n_buckets)      p_b = fraction of tasks in bucket b
caseresult
n_bucketsequal-width bins on [0, 1]
tasks spread evenlyC = 1
tasks all cluster in one bucketC = 0

M — monotonicity

Fraction of tasks with no strong ability inversion.

M = |{ monotonic tasks }| / n_tasks
termdefinition
compared pairsthose where ability_i > ability_j + ability_eps
ability_epsdefault 0.05
strong inversionsolved_j and not solved_i — noise, mislabel, or gameability
monotonic taskiff zero inversions
abilitydefaults to each model’s overall solve-rate
no ability separationM is vacuously 1.0

A — angle coverage

capability_profile decomposes the gate-states 0..4 into four conditional rates:

I — IRT test information

irt_item_stats fits the binary matrix to the 2-parameter logistic model.

item parameterestimate
b — difficultylogit(1 − solve_rate); harder tasks (low solve-rate) get higher b
a — discriminationmax(0.2, |r_pb|·2 + 0.2), where r_pb is the task’s point-biserial correlation with the per-model total score
all-pass / all-fail / non-correlating itemfloors to a small a — it discriminates nothing

Each item’s Fisher information at ability theta:

I_item(theta) = a² · P · (1 − P)        P = 1 / (1 + e^{−a(theta − b)})

Information is additive (items conditionally independent), so it sums over the test:

I_test(theta) = Σ_items a² · P · (1 − P)          SE(theta) = 1 / √I_test
callreturns
select_max_informationthe max-information subset is exactly the top-k items, so there is no greedy pass
information_se(info)that SE; ∞ with no information

KR-20 — reliability

Kuder-Richardson 20 — internal-consistency reliability for binary items:

KR20 = ( k / (k−1) ) · ( 1 − Σ p_i·q_i / σ²_total )
termmeaning
ktasks
p_ipass rate of task i
q_i1 − p_i
σ²_totalper-model total-score variance
k < 2, or that variance is 0None
rule of thumb> 0.7 acceptable, > 0.8 good
negativeitems are mutually inconsistent

What a bad value looks like

axiswhat it asksreadswhat a bad value looks like
DDiscriminative yield: tasks that split the field (0 < solvers < n_models).[0,1]Low D: mostly all-pass or all-fail rows. Below the min_D gate the day cannot rank anyone.
CDifficulty coverage: normalized entropy of the per-task solve-rate buckets.[0,1]C near 0: every task in one difficulty band. The set then measures one point on the ability curve.
MMonotonicity: tasks with no strong ability inversion. Inversion: a weaker model passes what an abler one misses.[0,1]M below 1 flags flaky, mislabeled or gameable tasks. M is vacuously 1.0 when no model pair is clearly separated.
I2PL Fisher test-information: discrimination a from point-biserial, difficulty b from solve-rate. Additive, and SE = 1/√I.≥ 0Information concentrated in one or two items. An all-pass or all-fail task contributes almost none of it.
KR-20Internal-consistency reliability over binary items.≤ 1Below the bar (min_kr20) the set is not yet one instrument. A negative KR-20 means items contradict each other.
AAngle coverage. Advisory: it does not read the solve matrix.advisoryAn angle with fewer than min_support tasks in its conditioning population is undefined.
RDiversity, 1 − near-duplicate rate. Advisory: it does not read the solve matrix.advisoryLow R: the day filled with near-clones of one PR family. Two tasks in the same repo above the similarity cut count as duplicates.
D CISeeded bootstrap over resampled task rows, 95% central interval.[0,1]A half-width above max_d_halfwidth (default 0.15): the day cannot place D precisely enough to claim anything.

A (angle coverage) and R (1 − near-duplicate rate) are advisory: neither reads the solve matrix.

Uncertainty and power

Bootstrap confidence intervals

msq_bootstrap_ci resamples the task rows with replacement, n_boot times.

Each resample recomputes D/C/M.

{ estimate, lo, hi, se, n_valid }
fieldmeaning
estimatethe full-set point estimate
[lo, hi]the central ci-percentile interval (default 95%)
sethe bootstrap SD
RNGseeded → resume-reproducible
at N ≈ 6 tasksintervals are wide

Precision-power (required-N)

required_tasks_for_precision scales SE as 1/√N from the bootstrap SE at N₀:

half_width h(N) = z · SE(N₀) · √(N₀ / N)
required N       = N₀ · ( z · SE(N₀) / target_half_width )²      (rounded up)
returnsnotes
{axis, n_now, se_now, half_width_now, target_half_width, required_n}one record per axis
required_n is Nonewhen the axis SE is undefined
required_n is 0when SE is already 0
precision_curve(matrix, sizes, axis="D")the curve [{n, half_width}, ...]

Reliability-power (required-N)

tasks_for_reliability applies the Spearman-Brown prophecy.

It gives the test length needed to reach a target KR-20:

k' = k · [ ρ'·(1 − ρ) ] / [ ρ·(1 − ρ') ]        (rounded up, floored at 1)
returnsnotes
{current_kr20, current_k, target_kr20, required_k}measured from the current KR-20
required_k is Nonewhen reliability is undefined or ≤ 0, or the target is outside (0, 1)

The readiness verdict

benchmark_readiness folds discrimination, reliability, and precision together.

One daily GO/NO-GO advisory.

ready iff all three hold:

D ≥ min_D            (default 0.4)
KR-20 ≥ min_kr20     (default 0.7)
D 95%-CI half-width ≤ max_d_halfwidth   (default 0.15)

What a NO-GO reports

fieldcontents
reasonseach failing constraint with value, threshold, required_n
bottleneckthe failing constraint that demands the most tasks
recommended_nmax(precision-required-N, reliability-required-N)
a None on any axisfails that axis
statusadvisory only: never gates an accept

What the card does not license

limitwhy
A ranking is not a result.At this N one model’s Wilson interval covers most of the others.
D is coarse at small N.One task flipping moves it a step.
Not yet one instrument.Below the KR-20 bar the total is not a skill estimate.
A vacuous high is not a win.M reaches 1.0 when no separation is left to violate.
Required-N is an order of magnitude.It assumes the next tasks are drawn like today’s; it is today’s bootstrap SE extrapolated at 1/√N.
Readiness is advisory.It never gates an accept or touches the reward path.

What it does catch is a collapsed set: all-pass or all-fail rows, a negatively correlating item, a missing difficulty band.

Reading the quality report

These notes qualify the figures on the selection-quality report.

They are standing methodology, so they live here rather than beside every figure.

The discrimination report

what you are looking athow to read it
provisional readingsProvisional readings, not properties — every number on that page is recomputed from the published matrix at page load.
scaffold scopeThe solve matrix is one scaffold, one model family, one day. It is never the whole model suite, and its cells are not independent trials.
hollow squaresA hollow square is a task from another suite, not a skipped run. Where a run really was skipped under the reported scaffold, the note on the figure says so instead and names the count.
overlapping intervalsOverlapping Wilson intervals are not a significance test. Where a figure paints a shaded band, that band marks the range every count in that group still allows.
the level rowsThe difficulty rows are a partition of the publication-mode row above them, not peer groups. They are compared inside one publication mode only: pooling the modes puts structurally-zero tasks into the comparison and the result is an artifact of pooling.
publication modelive vs archive is a difference in what is withheld, not measured difficulty. Live withholds gold patches, protected test bodies and merge provenance; archive publishes them. Harder, newer and measured differently cannot be told apart. Any other publication mode likewise differs in what the task package publishes, so those rows are coverage facts, not difficulty findings.
declared difficultyDeclared difficulty is editorial — the task.toml label, never measured.
authorityNothing on that page is ranked or certified: no publication bundle is approved, no matrix digest is trusted, and receipt authority is inactive — which is why the registry’s Official solves column is a dash.

The capability coverage report

what you are looking athow to read it
every axis is listedAll fourteen axes are listed. An axis this catalogue does not cover is a fact about the catalogue, not a row to hide — so an axis carrying no task at all is listed at zero rather than dropped: a missing row reads as an axis that does not exist, which is a different claim from an axis this catalogue never reached.
the co-occurrence gridOne column per re-derivable package, one row per axis; a mark is presence, never a degree. No model outcome is in that figure — it is not a solve result. Columns are ordered by how many labels a package carries, so the dense left edge is arrangement, not a finding.
multi-valued labelsA task carries every code its diff triggers, so the per-code counts do not sum to the task count.
the unmeasured criterionmin_admitted_subtests counts the subtests surviving a unit-test-validity audit, and no such audit has classified this catalogue. Unmeasured is not failed, and it is certainly not passed — so no axis clears the publish gate whatever its counts say.
the audit on recordThe unit-test-validity audit on record does not describe this catalogue (release b3fc3e6, experiments/reports/unit-test-validity-r001/SUMMARY.json). It measured a different corpus at a different release commit; its per-axis counts describe that corpus, so they are not reproduced on the report and min_admitted_subtests stays unmeasured here.
packages that cannot be taggedThe tagger reads the oracle diff and live withholds it, so a live package’s task.toml keywords stand as declared, never re-derived — and every count on the report is over the packages that could be checked.

One-call quality card

benchmark_quality_report(matrix, ..., deep=True) aggregates every axis.

keycontentsneeds
msqthe MSQ profile: D/C/M + composite
diversityfrom signatures
angle coveragefrom flat graded states
noisy_task_indicesmonotonicity violations
curated subsetmonotonic core → info-max → diverse filter
IRTtotal_information + SEdeep=True
cibootstrap intervalsdeep=True
powerprecision required-Ndeep=True
reliabilityKR-20deep=True
reliability_prophecySpearman-Brown required-kdeep=True
 
from terminal_daily_bench import quality as q

matrix = [
    [1, 0, 0],   # td-1: A solves, B/C fail  -> splits
    [1, 1, 0],   # td-2
    [1, 1, 1],   # td-3: all-pass            -> no discrimination
    [0, 0, 0],   # td-4: all-fail            -> no discrimination
    [1, 0, 1],   # td-5
    [1, 1, 0],   # td-6
]

card = q.benchmark_quality_report(matrix, deep=True)
print(card["msq"])          # {'D': 0.667, 'C': 0.896, 'M': 0.833, 'composite': 0.766, ...}
print(card["irt"]["total_information"])   # 1.808
print(card["reliability"]["kr20"])        # 0.514

verdict = q.benchmark_readiness(matrix)
print(verdict["ready"], verdict["bottleneck"], verdict["recommended_n"])
# False precision 37
