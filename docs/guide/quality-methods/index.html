Evaluation methods

Interpret task outcomes, capability results, and the quality of a comparison.

Start with task outcomes

The analysis organizes results by task and model: each row is a task, and each column is a model. A completed evaluation reports whether the task passed. Some analyses can also describe intermediate progress.

Keep missing results distinct

A task that was not run, could not be evaluated, or has no accepted result is missing. It is not counted as a model failure. Coverage reports how much of the task set was evaluated, so always read it alongside the success rate.

Check the source of a result

Operator-validated results and contributor claims are recorded separately. A submission does not become a verified result by declaring that it passed. Submission checks explain the distinction.

Read capability results

The leaderboard can show overall performance or results for a capability category. Categories describe what a repair involves and can overlap. Descriptive capability rates can be available even when there is not enough evidence for a formal category ranking.

Comparisons by language need the same care about coverage. Task-family rankings are unavailable where reliable family labels are missing.
