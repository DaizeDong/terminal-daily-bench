Replay integrity

What the operator worker has to prove before a receipt exists — and what nothing here has proven yet.

The frozen execution policy

The policy freezes the replay stack — replay runner and Harbor digests, backend, offline policy, authority key — and, per task, the SIF digest. It also freezes the container runtime: its canonical absolute path, binary SHA-256, exact version, and kind. The worker must not own or be able to write the runtime binary or its parent directory, and neither may be group- or world-writable.

Image and runtime checks

Before every Harbor execution the worker copies the expected SIF read-only into a worker-private attempt directory. The frozen digest is checked before Harbor and at the Harbor-to-canary boundary; the runtime facts are checked before Harbor and in the canary preflight. Before a receipt is returned those snapshots must match, and image drift or a runtime snapshot mismatch fails closed.

Implemented Harbor binding

A receipt binds harbor_binary_path — the canonical launcher path, plus its digest and version — and harbor_package_root, the canonical package root, together with a SHA-256 of the complete Harbor package and network-patch tree and the immutable runtime-control facts. The worker recomputes and compares those facts before and after replay, so changed imported modules or backend patches fail closed.

Implemented result binding

The authoritative result.json reader opens root/run/result through O_NOFOLLOW file descriptors, rejects symlinks and hardlinks (st_nlink != 1), checks inode/device/link-count stability, and limits the snapshot to 16 MiB. Reward validation and receipt hashing use the same already-open snapshot bytes; the selected pathname is never reopened.

The canary requirement

The pinned image must reach the canary endpoint as a control, and the same image must fail to reach it under --net --network none. Anything else — missing image bytes, an unreachable control, or an unproven isolation failure — is an infrastructure error, never a zero reward and never a verified receipt.

Deployment boundary

Signer and ingest/promoter must use distinct UIDs or service identities. A signer-only private-key mount and promoter read-only manifest/public-key mounts are required. Shared ownership plus mode bits is not isolation.

Evidence boundary, and what stays blocked

The fake-runner and Fake Harbor tests prove code and command boundaries only. Fake-runner tests are not evidence of a production replay, real network isolation, or a correctly separated receipt authority, and semantic verifier false-accept remains unmeasured pending an exploit corpus.

Production replay remains blocked until the official compute worker, against the real installed package and replay artifacts, completes a real Harbor replay, demonstrates a reachable control canary and a blocked isolated canary, and passes an operator audit of the deployment boundary above plus the Harbor package/tree and single-snapshot result controls.
