Adding a scaffold

A scaffold produces a candidate patch and nothing else; it never computes a reward.

The HarnessAdapter contract

The contract is one function, in terminal_daily_bench/adapters/base.py.

The fail_to_pass selectors in record.json are the failing_test_ids it receives. Live tasks ship those ids but withhold solution/ and the protected test_outputs.py body.

The interface

An adapter subclasses HarnessAdapter and implements produce_patch.

Rules for produce_patch

From the base-class docstring: an adapter MUST NOT read or write the protected tests or the gold solution, and MUST NOT compute a reward, because scoring is done afterward by the execution gate. On failure it returns an AdapterResult with error set and an empty patch — a 0-reward attempt, not a raised crash.

Reference implementation

terminal_daily_bench/adapters/single_shot.py is SingleShotAdapter, name = "single_shot". It loads the task (eval.load_task), finds the file(s) the reference solution touches (eval.solution_target_files), reads those files out of the SIF image for context (eval.extract_repo_files), builds a strict prompt (eval.build_prompt) asking for one unified diff, calls the model (eval.call_model) and extracts the diff (eval.extract_diff), then returns an AdapterResult with touches_tests telemetry — no scoring.

The multi-turn stub

terminal_daily_bench/adapters/terminus.py — TerminusAdapter, name = "terminus" — is a stub for a multi-turn agent: terminus-2, Claude Code, Aider, OpenHands, SWE-agent. To finish it, implement its produce_patch to run your agent CLI and return the diff. Any harness taking a custom OpenAI base URL drives an arbitrary model unchanged.

Registering it

Discovery is by the registry in terminal_daily_bench/adapters/__init__.py: add your adapter class to that tuple and to __all__ with a unique name, then set the scaffold field of your submission records to it. The leaderboard groups runs by (submitter, model, scaffold).
