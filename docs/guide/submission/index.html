submitting to terminal-daily-bench

No external service or hidden API is required to score a patch.

A claimed reward is never trusted: only an official protected-test replay receipt can enter the verified ranking.

A scaffold produces a candidate patch; the execution gate is the sole reward authority.

The model is the subject under test; it is never the judge.

Semantic verifier false-accept remains unmeasured pending an exploit corpus.

1. Run a model on a task

Entry point: tdb (terminal_daily_bench/cli.py).

pip install -e .                          # installs the `tdb` console script

export OPENAI_BASE_URL=https://api.openai.com/v1   # any OpenAI-compatible endpoint
export OPENAI_API_KEY=sk-...                        # bearer key, read from env, never stored

# Score a model on one task (single-shot patch scaffold + execution gate)
tdb run gpt-4o tasks/archive/td-fc90ea8b76d5f6b6

# Baseline: replay the task's own gold patch — proves the gate returns 1.0
tdb oracle tasks/archive/td-fc90ea8b76d5f6b6

# Multi-angle quality card over a results file (needs >=2 models)
tdb quality results.jsonl

Endpoint, oracle, host

keywhat it does
OPENAI_BASE_URL Defaults to https://api.openai.com/v1. OpenRouter, vLLM, LiteLLM and local servers work too.
model id oracle Runs the task's solution/oracle.patch; needs no endpoint and no key.
apptainer/singularity Required host — scoring runs there.
TDB_SIF_CACHE · TDB_OVERLAY_DIR Override the singularity scratch paths.
TDB_WORK Overrides the work root.

Failure never scores positive

outcomewhat is recorded
solved reward >= 0.999.
any failure No diff, an unapplied patch, a trial error or an unparseable result yields reward 0.0 / solved false, cause in error.
a crash Never scores positive (BAD-safe by construction).

2. How scoring works — deterministic execution gate

The reward comes from harbor's result.json.

the gatewhat it does
reward source harbor_score._read_harbor_reward — the same reader the private admission gate uses.
where the patch runs harbor applies it inside the task container.
the tests harbor re-lays the protected tests/ and runs them under a network cut.
host Which is why scoring requires an apptainer/singularity host.

Why a patch cannot cheat the score

attackwhy it fails
edit the tests The protected tests/ are re-laid by harbor from the trusted task package after the patch is applied. A patch that edits tests/ only changes an agent-side workspace that is discarded before scoring.
phone home Runtime egress is cut — --network=none, or the offline --ek switch injected by harbor_score._maybe_inject_offline_eks.
claim a score The reward is byte-for-byte execution truth from result.json, not any string the model emitted.

Recording is not replay

web/submit_result.py records the patch. It does not score it.

on recordwhat happens
reward_claimed Advisory only — it is validated against nothing.
the stored entry verify_status="pending", verified_reward=null, no false_accept value. Only an execution-gate receipt can set a verified reward.
the public bundle Does not run a replay worker. Pending rows remain in community_pending, a separate audit view excluded from ranking.
community_verified Entry requires an Ed25519-signed v2 receipt bound to the frozen suite, runner, Harbor, runtime image, enforced offline canary and pinned authority key.
ranking Also requires the complete frozen roster.

3. Submitting results

Submission schema (JSONL, one line per (model, task) cell)

Required fields: every key below except reward_claimed.

# submit_result.validate, the REQUIRED tuple
{
  "date": "2026-07-22",
  "submitter": "your-handle",
  "model": "your-model",
  "model_build": "your-model@immutable-build-id",
  "scaffold": "your-scaffold",
  "harness_version": "your-scaffold@immutable-version",
  "task": "td-fc90ea8b76d5f6b6",
  "patch": "diff --git a/... b/...\n--- a/...\n+++ b/...\n@@ ...",
  "reward_claimed": 1.0
}

Validation rules

fieldrule
all eight required date, submitter, model, model_build, scaffold, harness_version, task and patch must be present and non-empty.
patch Must be a unified-diff string.
task Must start with td-.
reward_claimed Advisory only; it never becomes a score.
receipt signatures Come only from the official signer.
the submitter The authenticated submitter comes from the deployment auth layer, never the JSON body.

CLI

web/submit_result.py reads a submission JSON from stdin:

# 1. Validate structure (exit 0 = valid, 1 = errors)
python web/submit_result.py validate < submission.json

# 2. Record as pending (appends to <store>/<date>.jsonl)
python web/submit_result.py record --store community_submissions \
  --authenticated-submitter github:YOUR_LOGIN < submission.json

# 3. After an operator replay receipt exists, rebuild the two public views
python web/submit_result.py rebuild --store community_submissions \
  --manifest /read-only/suite-manifest.json \
  --trusted-keys /read-only/replay-authorities.json \
  --out web/leaderboard_data.json

One immutable cell per submission

stepwhat it binds
record Computes a full SHA-256 content id over patch, authenticated submitter, model build, harness version and task.
uniqueness One immutable authenticated cell per suite/build/harness/task.
left unranked Partial, duplicate and cross-date sets.
rebuild Every rebuild re-verifies the receipt signature and content binding.

4. Operator-only replay authority

The replay extra

Install the replay-only receipt dependency on the operator image:

pip install -e '.[replay]'
propertywhat it means
primitives Receipt signing and verification use Python cryptography's in-process Ed25519 primitives.
no subprocess web/receipt_auth.py does not search PATH and does not invoke an external OpenSSL process.
missing extra A missing or invalid replay extra fails closed before signing or acceptance.

The frozen execution policy

It must pin:

pinnedwhat
the replay stack Replay runner and Harbor digests, backend, offline policy, authority key.
per task The SIF digest.
the container runtime Its canonical absolute path, binary SHA-256, exact version, and kind.
ownership The worker must not own or be able to write the runtime binary or its parent directory; neither may be group- or world-writable.

Image and runtime checks

whenwhat is checked
before every Harbor execution The worker copies the expected SIF read-only into a worker-private attempt directory.
the frozen digest Checked before Harbor and at the Harbor-to-canary boundary.
runtime facts Checked before Harbor and in the canary preflight.
before a receipt is returned Those snapshots must match. Image drift or a runtime snapshot mismatch fails closed.

Implemented Harbor binding

Policy and receipts bind:

bound factwhat
harbor_binary_path The canonical launcher path, plus its digest and version.
harbor_package_root The canonical package root.
tree hash SHA-256 of the complete Harbor package and network-patch tree.
runtime control Immutable runtime-control facts.
drift The worker recomputes and compares those facts before and after replay, so changed imported modules or backend patches fail closed.

Implemented result binding

controlwhat the reader does
descriptors The authoritative result.json reader opens root/run/result through O_NOFOLLOW file descriptors.
links Rejects symlinks and hardlinks (st_nlink != 1), and checks inode/device/link-count stability.
size Limits the snapshot to 16 MiB.
hashing Reward validation and receipt hashing use the same already-open snapshot bytes; the selected pathname is never reopened.

The canary requirement

runwhat must happen
control The pinned image must reach the canary endpoint.
isolated The same image must fail to reach it under --net --network none.
anything else Missing image bytes, an unreachable control, or an unproven isolation failure is an infrastructure error — never a zero reward, never a verified receipt.

Deployment boundary

identityrequirement
signer vs. promoter Signer and ingest/promoter must use distinct UIDs or service identities.
mounts A signer-only private-key mount and promoter read-only manifest/public-key mounts are required.
not sufficient Shared ownership plus mode bits is not isolation.

Evidence boundary

testwhat it does and does not prove
fake-runner and Fake Harbor tests Prove code and command boundaries only.
not evidence of Fake-runner tests are not evidence of a production replay, real network isolation, or a correctly separated receipt authority.

Production blocker

Production replay remains blocked until the official compute worker:

stepwhat it must do
1 Completes a real Harbor replay.
2 Demonstrates a reachable control canary and a blocked isolated canary.
3 Passes an operator audit of the deployment boundary above, plus the Harbor package/tree and single-snapshot result controls.
against The real installed package and replay artifacts.

Live vs. archived tasks

releasewhat ships
Live (this week) Withholds the gold patch and protected test bodies; a patch stays pending until an official replay.
Archived (≥ 2 weeks old) Ships in full. Archive vs. live →

5. Adding a scaffold / agent — the HarnessAdapter contract

Contract (terminal_daily_bench/adapters/base.py):

input  = (task dir, failing test ids, model id/endpoint)
output = (unified diff, telemetry)

The interface

from dataclasses import dataclass, field
from typing import Any, Dict, List, Optional

@dataclass
class AdapterResult:
    patch: str                                               # unified diff the harness produced
    telemetry: Dict[str, Any] = field(default_factory=dict)  # tokens, cost_usd, turns, wall_s
    error: Optional[str] = None

class HarnessAdapter(abc.ABC):
    name: str = "base"

    @abc.abstractmethod
    def produce_patch(self, task_dir: str, failing_test_ids: List[str],
                      model: str, **kwargs: Any) -> AdapterResult:
        ...

produce_patch rules

From the base-class docstring:

rulewhat it means
MUST NOT read the answer No reading or writing the protected tests or the gold solution.
MUST NOT score No computing a reward — scoring is done afterward by the execution gate.
on failure Return an AdapterResult with error set and an empty patch — a 0-reward attempt, not a raised crash.

Reference implementation

terminal_daily_bench/adapters/single_shot.py — SingleShotAdapter, name = "single_shot". It:

stepcall
1 loads the task (eval.load_task)
2 finds the file(s) the reference solution touches (eval.solution_target_files)
3 reads those files out of the SIF image for context (eval.extract_repo_files)
4 builds a strict prompt (eval.build_prompt) asking for one unified diff
5 calls the model (eval.call_model) and extracts the diff (eval.extract_diff)
6 returns an AdapterResult with touches_tests telemetry — no scoring

The multi-turn stub

terminal_daily_bench/adapters/terminus.py — TerminusAdapter, name = "terminus".

whathow
it is a stub For a multi-turn agent: terminus-2, Claude Code, Aider, OpenHands, SWE-agent.
to finish it Implement its produce_patch to run your agent CLI and return the diff.
any model Any harness taking a custom OpenAI base URL drives an arbitrary model unchanged.

Registering it

Discovery is by the registry in terminal_daily_bench/adapters/__init__.py:

REGISTRY = {a.name: a for a in (SingleShotAdapter, TerminusAdapter)}
dowhat
register Add your adapter class to that tuple and to __all__ with a unique name.
declare Set the scaffold field of your submission records to it.
grouping The leaderboard groups runs by (submitter, model, scaffold).

6. Task package layout (reference)

Each task lives in tasks/{archive|live}/<task-id>/.

Full schema: task format and tasks/SCHEMA.md.

PathPurpose
task.toml environment.docker_image (the SIF) · environment.allow_internet
instruction.md the natural-language task shown to the model
tests/ test.sh runner · test_outputs.py protected assertions (archive only)
environment/Dockerfile / build recipe
solution/ solve.sh · oracle.patch (archive only — withheld for live)
PROVENANCE.json repo · pr_number · base/merge SHAs · upstream license
record.json task_id, source PR metadata, fail_to_pass selectors

Failing test ids

releasewhat an adapter is given
every task The fail_to_pass selectors in record.json are the failing_test_ids passed to an adapter.
live only Live tasks ship those IDs but withhold solution/ and the protected test_outputs.py body.
