Submitting to terminal-daily-bench

No external service or hidden API is required to score a patch.

A claimed reward is never trusted: only an official protected-test replay receipt can enter the verified ranking.

A scaffold produces a candidate patch; the execution gate is the sole reward authority.

The model is the subject under test; it is never the judge.

Semantic verifier false-accept remains unmeasured pending an exploit corpus.

Run a model on a task

Entry point: tdb (terminal_daily_bench/cli.py).

pip install -e .                          # installs the `tdb` console script

export OPENAI_BASE_URL=https://api.openai.com/v1   # any OpenAI-compatible endpoint
export OPENAI_API_KEY=sk-...                        # bearer key, read from env, never stored

# Score a model on one task (single-shot patch scaffold + execution gate)
tdb run gpt-4o tasks/archive/td-fc90ea8b76d5f6b6

# Baseline: replay the task's own gold patch — proves the gate returns 1.0
tdb oracle tasks/archive/td-fc90ea8b76d5f6b6

# Multi-angle quality card over a results file (needs >=2 models)
tdb quality results.jsonl

Endpoint, oracle, host

OPENAI_BASE_URL
Defaults to https://api.openai.com/v1. OpenRouter, vLLM, LiteLLM and local servers work too.
Model id oracle
Runs the task’s solution/oracle.patch; needs no endpoint and no key.
apptainer/singularity
Required host — scoring runs there.
TDB_SIF_CACHE · TDB_OVERLAY_DIR
Override the singularity scratch paths.
TDB_WORK
Overrides the work root.

The result record

One JSON record per run, written by terminal_daily_bench/eval.py:

# lands in --out, default $TDB_WORK/results/
{
  "model": "gpt-4o",
  "task": "td-fc90ea8b76d5f6b6",
  "scaffold": "single_shot_patch",
  "reward": 1.0,
  "solved": true,
  "patch_applied": true,
  "error": null,
  "runtime_sec": 214.3,
  "false_accept_check": {
    "gate": "harbor_protected_tests",
    "reward_source": "result.json via harbor_score.read_harbor_reward",
    "protected_tests_relaid_by_harbor": true,
    "model_is_judge": false,
    "model_patch_touched_tests": false,
    "scope": "protected_test_replay_integrity",
    "claim_acceptance_without_replay": false,
    "semantic_false_accept": null,
    "false_accept": 0
  }
}

Failure never scores positive

solved means reward >= 0.999. No diff, an unapplied patch, a trial error or an unparseable result yields reward 0.0 / solved false with the cause in error, and a crash never scores positive: the run path is BAD-safe by construction.

How scoring works — deterministic execution gate

The reward comes from Harbor’s result.json.

Reward source
harbor_score._read_harbor_reward — the same reader the private admission gate uses.
Where the patch runs
Harbor applies it inside the task container.
The tests
Harbor re-lays the protected tests/ and runs them under a network cut.
Host
Which is why scoring requires an apptainer/singularity host.

Why a patch cannot cheat the score

Edit the tests
The protected tests/ are re-laid by Harbor from the trusted task package after the patch is applied. A patch that edits tests/ only changes an agent-side workspace that is discarded before scoring.
Phone home
Runtime egress is cut — --network=none, or the offline --ek switch injected by harbor_score._maybe_inject_offline_eks.
Claim a score
The reward is byte-for-byte execution truth from result.json, not any string the model emitted.

Recording is not replay

web/submit_result.py records the patch. It does not score it.

reward_claimed
Advisory only — it is validated against nothing.
The stored entry
verify_status="pending", verified_reward=null, no false_accept value. Only an execution-gate receipt can set a verified reward.
The public bundle
Does not run a replay worker. Pending rows remain in community_pending, a separate audit view excluded from ranking.
community_verified
Entry requires an Ed25519-signed v2 receipt bound to the frozen suite, runner, Harbor, runtime image, enforced offline canary and pinned authority key.
Ranking
Also requires the complete frozen roster.

Submission schema

JSONL, one line per (model, task) cell. Every key below except reward_claimed is required.

# submit_result.validate, the REQUIRED tuple
{
  "date": "2026-07-22",
  "submitter": "your-handle",
  "model": "your-model",
  "model_build": "your-model@immutable-build-id",
  "scaffold": "your-scaffold",
  "harness_version": "your-scaffold@immutable-version",
  "task": "td-fc90ea8b76d5f6b6",
  "patch": "diff --git a/... b/...\n--- a/...\n+++ b/...\n@@ ...",
  "reward_claimed": 1.0
}

Validation rules

All eight required
date, submitter, model, model_build, scaffold, harness_version, task and patch must be present and non-empty.
patch
Must be a unified-diff string.
task
Must start with td-.
reward_claimed
Advisory only; it never becomes a score.
Receipt signatures
Come only from the official signer.
The submitter
The authenticated submitter comes from the deployment auth layer, never the JSON body.

CLI

web/submit_result.py reads a submission JSON from stdin:

# 1. Validate structure (exit 0 = valid, 1 = errors)
python web/submit_result.py validate < submission.json

# 2. Record as pending (appends to <store>/<date>.jsonl)
python web/submit_result.py record --store community_submissions \
  --authenticated-submitter github:YOUR_LOGIN < submission.json

# 3. After an operator replay receipt exists, rebuild the two public views
python web/submit_result.py rebuild --store community_submissions \
  --manifest /read-only/suite-manifest.json \
  --trusted-keys /read-only/replay-authorities.json \
  --out web/leaderboard_data.json

One immutable cell per submission

record computes a full SHA-256 content id over patch, authenticated submitter, model build, harness version and task, which yields one immutable authenticated cell per suite/build/harness/task. Partial, duplicate and cross-date sets are left unranked, and every rebuild re-verifies the receipt signature and content binding.

Operator-only replay authority

Install the replay-only receipt dependency on the operator image:

pip install -e '.[replay]'
Primitives
Receipt signing and verification use Python cryptography’s in-process Ed25519 primitives.
No subprocess
web/receipt_auth.py does not search PATH and does not invoke an external OpenSSL process.
Missing extra
A missing or invalid replay extra fails closed before signing or acceptance.

The frozen execution policy

The replay stack
Replay runner and Harbor digests, backend, offline policy, authority key.
Per task
The SIF digest.
The container runtime
Its canonical absolute path, binary SHA-256, exact version, and kind.
Ownership
The worker must not own or be able to write the runtime binary or its parent directory; neither may be group- or world-writable.

Image and runtime checks

Before every Harbor execution
The worker copies the expected SIF read-only into a worker-private attempt directory.
The frozen digest
Checked before Harbor and at the Harbor-to-canary boundary.
Runtime facts
Checked before Harbor and in the canary preflight.
Before a receipt is returned
Those snapshots must match. Image drift or a runtime snapshot mismatch fails closed.

Implemented Harbor binding

harbor_binary_path
The canonical launcher path, plus its digest and version.
harbor_package_root
The canonical package root.
Tree hash
SHA-256 of the complete Harbor package and network-patch tree.
Runtime control
Immutable runtime-control facts.
Drift
The worker recomputes and compares those facts before and after replay, so changed imported modules or backend patches fail closed.

Implemented result binding

Descriptors
The authoritative result.json reader opens root/run/result through O_NOFOLLOW file descriptors.
Links
Rejects symlinks and hardlinks (st_nlink != 1), and checks inode/device/link-count stability.
Size
Limits the snapshot to 16 MiB.
Hashing
Reward validation and receipt hashing use the same already-open snapshot bytes; the selected pathname is never reopened.

The canary requirement

Control
The pinned image must reach the canary endpoint.
Isolated
The same image must fail to reach it under --net --network none.
Anything else
Missing image bytes, an unreachable control, or an unproven isolation failure is an infrastructure error — never a zero reward, never a verified receipt.

Deployment boundary

Signer and ingest/promoter must use distinct UIDs or service identities. A signer-only private-key mount and promoter read-only manifest/public-key mounts are required. Shared ownership plus mode bits is not isolation.

Evidence boundary, and what stays blocked

The fake-runner and Fake Harbor tests prove code and command boundaries only. Fake-runner tests are not evidence of a production replay, real network isolation, or a correctly separated receipt authority.

Production replay remains blocked until the official compute worker, against the real installed package and replay artifacts:

  • completes a real Harbor replay;
  • demonstrates a reachable control canary and a blocked isolated canary;
  • passes an operator audit of the deployment boundary above, plus the Harbor package/tree and single-snapshot result controls.

Live vs. archived tasks

Live tasks — this week’s — withhold the gold patch and the protected test bodies, and a patch against one stays pending until an official replay. Archived tasks, at least two weeks old, ship in full. Archive vs. live →

Adding a scaffold — the HarnessAdapter contract

Contract (terminal_daily_bench/adapters/base.py):

input  = (task dir, failing test ids, model id/endpoint)
output = (unified diff, telemetry)

The interface

from dataclasses import dataclass, field
from typing import Any, Dict, List, Optional

@dataclass
class AdapterResult:
    patch: str                                               # unified diff the harness produced
    telemetry: Dict[str, Any] = field(default_factory=dict)  # tokens, cost_usd, turns, wall_s
    error: Optional[str] = None

class HarnessAdapter(abc.ABC):
    name: str = "base"

    @abc.abstractmethod
    def produce_patch(self, task_dir: str, failing_test_ids: List[str],
                      model: str, **kwargs: Any) -> AdapterResult:
        ...

produce_patch rules

From the base-class docstring:

MUST NOT read the answer
No reading or writing the protected tests or the gold solution.
MUST NOT score
No computing a reward — scoring is done afterward by the execution gate.
On failure
Return an AdapterResult with error set and an empty patch — a 0-reward attempt, not a raised crash.

Reference implementation

terminal_daily_bench/adapters/single_shot.py — SingleShotAdapter, name = "single_shot". It:

  1. loads the task (eval.load_task);
  2. finds the file(s) the reference solution touches (eval.solution_target_files);
  3. reads those files out of the SIF image for context (eval.extract_repo_files);
  4. builds a strict prompt (eval.build_prompt) asking for one unified diff;
  5. calls the model (eval.call_model) and extracts the diff (eval.extract_diff);
  6. returns an AdapterResult with touches_tests telemetry — no scoring.

The multi-turn stub

terminal_daily_bench/adapters/terminus.py — TerminusAdapter, name = "terminus" — is a stub for a multi-turn agent: terminus-2, Claude Code, Aider, OpenHands, SWE-agent. To finish it, implement its produce_patch to run your agent CLI and return the diff. Any harness taking a custom OpenAI base URL drives an arbitrary model unchanged.

Registering it

Discovery is by the registry in terminal_daily_bench/adapters/__init__.py:

REGISTRY = {a.name: a for a in (SingleShotAdapter, TerminusAdapter)}

Add your adapter class to that tuple and to __all__ with a unique name, then set the scaffold field of your submission records to it. The leaderboard groups runs by (submitter, model, scaffold).

Task package layout

Each task lives in tasks/{archive|live}/<task-id>/. The seven paths in a package, what each carries and which of them live releases withhold are documented once, in Task format; the canonical short schema is tasks/SCHEMA.md.

Failing test ids

The fail_to_pass selectors in record.json are the failing_test_ids passed to an adapter. Live tasks ship those ids but withhold solution/ and the protected test_outputs.py body.
