The quality card

What a set of result records says about the benchmark, rather than about one model.

Aggregate a quality card

Collect result records into one file — JSON Lines (one record per line), or a JSON array.

What the card needs

tdb quality builds a (task × model) solved matrix and needs ≥ 1 task and ≥ 2 models. Records with model: "oracle" are excluded from it.

Reading the card

Where each metric comes from

Every metric comes from terminal_daily_bench.quality: D discrimination, C difficulty coverage, M monotonicity, 2PL IRT test-information, KR-20 reliability, a bootstrap 95% CI on D, and a readiness verdict naming the bottleneck axis and a recommended task count.

The final line of stdout is the full card as JSON (msq, irt, reliability, readiness) for machine consumption. The method behind these numbers is quality methods.

Submitting results

Every submission is recorded as pending and its claimed reward is ignored. The public bundle does not run a replay worker, and only an operator-published gate receipt can enter the verified ranking.
