Run a task

Build the image, score a model against the protected tests, and prove the gate with the oracle.

Build the task image

A published task ships no image: docker_image is the portable string environment/Dockerfile, because the producer’s host-specific .sif path is stripped on publish and nothing executes that as-is.

Build the task’s own Dockerfile once, then point docker_image at the result.

The cache key is the task id plus the Dockerfile hash, so a second run is a no-op and --force rebuilds. The build stage needs internet; the scored run does not. See the task format.

Score a model on a task

<MODEL> is any model id your endpoint accepts, e.g. gpt-4o-mini.

What single_shot_patch does

It shows the model the task instruction plus the source file(s) the reference solution touches, and asks for a git apply-ready unified diff.

That diff is applied inside the task container, Harbor re-lays the protected tests/, and the reward is written to result.json.

Run the oracle baseline

The oracle model id runs the task’s real solution/oracle.patch; no model is called, and it proves the execution gate returns reward 1.0 on a correct patch. Run it before spending model calls: if it does not yield reward = 1.0, the environment, not the model, is the problem.

Only archived tasks (≥ 2 weeks old) ship solution/. Live tasks withhold the gold patch and the protected test bodies; submitted patches stay unranked until official replay. See archive vs. live and tasks/SCHEMA.md.
