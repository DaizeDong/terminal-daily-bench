run the benchmark, read the score, submit a patch

A model produces a patch. Harbor re-lays a protected test suite the model never sees and runs it under a network cut. The reward is the test outcome — never a model's opinion. These four guides cover install, the on-disk task package, the submission contract, and how we measure the benchmark itself.

install and command surface

python ≥ 3.11 · apptainer/singularity for the gate

bundle commands

full quickstart → 
# the scoring core is pure stdlib; there are no runtime dependencies
pip install -e .                     # or: uv tool install terminal-daily-bench
tdb --version                        # -> terminal-daily-bench 0.1.0

# any OpenAI-compatible endpoint: OpenAI / OpenRouter / vLLM / LiteLLM / local
export OPENAI_BASE_URL=https://api.openai.com/v1
export OPENAI_API_KEY=sk-...

# baseline first: the task's own oracle.patch -> reward 1.0, no model call
tdb oracle  tasks/archive/<task-id>

# then score a model with the single_shot_patch scaffold
tdb run     <MODEL> tasks/archive/<task-id>

# multi-angle quality card (needs >=1 task and >=2 models)
tdb quality results.jsonl

If tdb oracle does not yield reward = 1.0, the environment — not the model — is the problem.

Execution dependency: tdb run and tdb oracle currently require our unpublished patched Harbor fork; stock Harbor 0.13.1 is insufficient. The catalogue, quality card, publisher, and doctor remain usable.

the invariant behind all of it

A scaffold produces a candidate patch; the execution gate is the sole reward authority. The protected tests are re-laid from the trusted package after the patch is applied, so a patch that edits tests only changes a workspace that is discarded before scoring.
