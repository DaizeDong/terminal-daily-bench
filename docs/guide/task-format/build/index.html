Task environments and sources

Understand where a task comes from and how its environment is prepared.

Build recipe

Each task includes a Dockerfile describing the source checkout and dependencies used for evaluation. Build from that recipe to reproduce the intended environment. Build instructions.

Reference solution

Archived tasks include the repair from the merged pull request and a script that applies it. Running this solution checks that the task environment can reproduce a passing result. Live tasks withhold it.

Source information

Source metadata identifies the repository, source revision, and license information. Tasks are drawn from permissively licensed repositories. This information helps readers trace a task to its origin.

Task record

Archived packages also describe the source change, relevant tests, and capability labels. Use this record when examining how the task was constructed; it is separate from a model’s evaluation result.
