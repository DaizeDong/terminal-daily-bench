Task format

Self-contained, harbor-native packages under tasks/{archive|live}/<task-id>/.

Everything here reflects the code in this bundle; no APIs are invented.

Package layout

tasks/archive/<task-id>/
  task.toml           environment.docker_image · environment.allow_internet · timeouts
  instruction.md      the natural-language task shown to the model (de-identified)
  tests/              test.sh (runner) · test_outputs.py (protected assertions) · test_patch.diff
  environment/        Dockerfile (build recipe: base image + repo @ base_sha + deps)
  solution/           solve.sh (git apply driver) · oracle.patch (the gold fix)
  PROVENANCE.json     source_repo · source_ref · source_license_spdx
  record.json         machine metadata (task_id, repo, pr_number, SHAs, f2p selectors)

Task ids look like td-fc90ea8b76d5f6b6. The canonical short schema is tasks/SCHEMA.md; the code is terminal_daily_bench/, tasks/publish_tasks.py and web/submit_result.py.

instruction.md is de-identified: upstream provenance — origin remote, project name, commit ids — is stripped, so the task is solved from the tree and the description alone.

task.toml

Harbor’s descriptor. The framework reads only [environment] (eval.py::load_task).

schema_version = "1.1"

[task]
name = "terminal-daily/td-fc90ea8b76d5f6b6"
description = "Validate format string keys in logger.add() for early error feedback"
keywords = ["C5", "C4"]                 # capability labels

[metadata]
source_repo = "Delgan/loguru"
pr_number = 1451
base_sha  = "2abeb0fa6d7be4b0455c6e0b580b1e9dab19005e"
merge_sha = "b782e56fcf07fecf9545ff6ee2350baacb0968ce"
oracle_patch_sha256 = "1e843ef7617ac857dfb2139ac3e2f2a6a328b4fc5e1848f8fd021b9f3b0fdda8"
difficulty = "medium"
network_profile = "build-online/run-offline"

[environment]
docker_image  = "environment/Dockerfile"   # portable ref: build from the task Dockerfile
allow_internet = false                      # run-offline -> egress cut at scoring time
cpus = 1
memory_mb = 4096
storage_mb = 16384
docker_image
Rewritten to the portable "environment/Dockerfile" on publish (publish_tasks.py::_sanitize_task_toml). The host-specific absolute .sif path is never shipped — you build the image from the task’s own environment/Dockerfile.
allow_internet
Drives the runtime network cut. When false, the singularity backend gets the no-network --ek switch injected automatically (harbor_score.py::maybe_inject_offline_eks), physically cutting egress during scoring.

tests/

Re-laid from the trusted package after the patch is applied.

test.sh
The runner; it writes the reward.
test_outputs.py
The protected assertions. Carries the FAIL_TO_PASS / PASS_TO_PASS selectors, lands the PR’s test_patch.diff onto the tree (_ensure_tests_applied), then runs the fail-to-pass tests. Archive only — the body is withheld for live tasks.
test_patch.diff
The PR’s test diff, applied at verify time so the test signal is never baked into the environment image.
tests/test.sh
  install    pytest + the project's test extras
  harden     remove stray conftest.py / sitecustomize.py · unset PYTHONPATH · pin PATH
  run        pytest -q -rA /tests/test_outputs.py
  reward     1 on all-pass, else 0  ->  /logs/verifier/reward.txt

environment/Dockerfile

A parity and audit artifact: the recipe the image is built from.

base image
repo @ REPO_BASE_SHA    .git re-initialized to a single `baseline` commit
deps by search          pip install -e .  ->  pip install .  ->  pip install -r requirements.txt
                        first that builds wins; hard-fails if none

solution/ (archive only)

solve.sh       the git-apply driver
  git apply --check oracle.patch
  git apply --3way oracle.patch      falls back to plain `git apply`
  already-applied tree               idempotent no-op
  genuinely inapplicable patch       FAILS LOUDLY -- never pretends success on an unpatched tree
  patch touches native/build inputs  rebuilds the extension offline

oracle.patch   the gold fix from the merged PR
  sha256                             recorded as oracle_patch_sha256 in task.toml / record.json

PROVENANCE.json

Tasks derive only from permissively-licensed repositories.

{
  "source_repo": "Delgan/loguru",
  "source_ref": "b782e56fcf07fecf9545ff6ee2350baacb0968ce",
  "source_license_spdx": ""
}

record.json (archive only)

Host-specific and internal build fields are stripped on publish (publish_tasks.py::_sanitize_record), leaving:

# stripped: image_ref · image_build · generator · repro · netns_available · needs_network
{
  "task_id": "td-fc90ea8b76d5f6b6",
  "repo": "Delgan/loguru",
  "pr_number": 1451,
  "base_sha": "2abeb0fa6d7be4b0455c6e0b580b1e9dab19005e",
  "merge_sha": "b782e56fcf07fecf9545ff6ee2350baacb0968ce",
  "oracle_patch_sha256": "1e843ef7617ac857dfb2139ac3e2f2a6a328b4fc5e1848f8fd021b9f3b0fdda8",
  "test_files": ["tests/test_add_option_format.py"],
  "fail_to_pass": ["tests/test_add_option_format.py::test_invalid_format_key_...", "..."],
  "pass_to_pass": [],
  "capability_labels": ["C5", "C4"]
}

Archive vs. live

A task is archived two weeks after its source PR merged. Live withholding blocks memorization and test-editing; releasing archived tasks in full supports local reproduction.

# tasks/publish_tasks.py::publish · ARCHIVE_WEEKS = 2
(today - merge_date).days >= 14   ->  archive
(today - merge_date).days <  14   ->  live

What ships in each mode

package path shipped in archive shipped in live
task.tomlyes (sanitized)yes (sanitized)
instruction.mdyesyes
PROVENANCE.jsonyesyes
environment/yesyes
tests/test.shyesyes
tests/test_outputs.py (protected body) yeswithheld
tests/test_patch.diff yeswithheld
solution/ (solve.sh, oracle.patch) yeswithheld
record.jsonyes (sanitized) replaced by FAILING_TESTS.json

FAILING_TESTS.json (live only)

Live submissions stay unranked until an official replay receipt exists.

# the failing-test IDs only, from the F2P selectors (publish_tasks.py::_failing_test_ids)
{
  "failing_test_ids": ["tests/test_add_option_format.py::test_invalid_format_key_..."],
  "note": "protected assertions + gold solution withheld; pending official replay"
}

How scoring re-lays the protected tests

Execution-only: no LLM judge can turn a claim into a score.

# terminal_daily_bench/eval.py · terminal_daily_bench/harbor_score.py
1  task package  ->  run copy (.tdb_work/runs/...)   the model never touches the trusted original
2  model  <-  instruction + the source file(s) the reference solution touches
3  model  ->  one unified diff                       eval.py::extract_diff
              ->  run copy solution/oracle.patch
4  harbor run -p <run_task> -a oracle -e singularity ...   eval.py::run_harbor_oracle
     solution/solve.sh  ->  git apply                the now model-authored patch, in the task container
5  harbor RE-LAYS tests/ FROM THE TRUSTED PACKAGE, runs them under a network cut
     on a face the agent never touched
6  result.json  ->  harbor_score.read_harbor_reward
              ->  reward >= 0.999  ->  solved: true

What the gate does and does not cover

Scope
Proves replay integrity, not semantic verifier completeness.
Test edits
A patch that edits tests/ only changes the discarded run-copy workspace — the protected tests come from the trusted package, not the patch.
Reward source
harbor_score.read_harbor_reward, the same reader the private admission gate uses.
BAD-safe
No patch, a failed apply, a hung trial or an unparseable result yield reward 0.0 / solved: false, cause recorded — never a positive score on a crash.
Offline cut
Offline tasks get the no-network switch from harbor_score.maybe_inject_offline_eks (singularity-gated, task-driven, idempotent).
Host hygiene
harbor_score.clean_subprocess_env scrubs host conda/venv pollution.

Install and point at a model

The runnable examples below need an apptainer/singularity host.

pip install -e .
export OPENAI_BASE_URL=...          # OpenAI / OpenRouter / vLLM / LiteLLM / local
export OPENAI_API_KEY=...

Score a task

tdb run and tdb oracle both wrap terminal_daily_bench.eval, which accepts --max-tokens, --call-timeout and --harbor-timeout.

# baseline: the task's own oracle.patch -> reward 1.0 (no model call, archive only)
tdb oracle tasks/archive/td-fc90ea8b76d5f6b6

# score a model with the single_shot_patch scaffold
tdb run <MODEL> tasks/archive/td-fc90ea8b76d5f6b6

# multi-angle quality card (needs >=1 task and >=2 models in the results file)
tdb quality results.jsonl

# result JSON lands under $TDB_WORK (default ./.tdb_work), or at --out PATH

Read a live task

cat tasks/live/td-fc90ea8b76d5f6b6/instruction.md
cat tasks/live/td-fc90ea8b76d5f6b6/FAILING_TESTS.json     # only the failing-test IDs

Publish a task directory

# publish_tasks.py <src_task_dir> <merge_date> <today> <out_root>
# idempotent; archive vs. live is picked from the dates
python tasks/publish_tasks.py ./src/td-fc90ea8b76d5f6b6 2026-03-25 2026-07-22 ./tasks
# -> {"task": "td-...", "mode": "archive", "shipped_solution": true, "dest": "tasks/archive/td-..."}

Submit a result

A submission is recorded as pending: the public bundle does not run a replay worker (see CONTRIBUTING.md), and complete frozen-roster signed replay coverage is required for community ranking. Validation rules →

# validate the submission JSON, then record it as pending re-verification
python web/submit_result.py validate < submission.json
python web/submit_result.py record   < submission.json \
  --store community_submissions --authenticated-submitter github:YOUR_LOGIN

# one JSON object per (model, task) cell; every key below is required
{ "date": "...", "submitter": "...", "model": "...", "model_build": "...",
  "scaffold": "...", "harness_version": "...", "task": "td-...", "patch": "..." }
# the auth layer supplies the authenticated submitter; reward_claimed is advisory

Plugging in your own scaffold

The built-in scaffold is single_shot_patch, one localized shot at a diff. Multi-turn agents plug in via the adapter contract, over any OpenAI-compatible endpoint.

# terminal_daily_bench/adapters/base.py::HarnessAdapter
input  = (task dir, failing test ids, model id/endpoint)
output = AdapterResult(patch: str, telemetry: dict, error: str | None)

# produce_patch(...) must NOT read or write the protected tests or the gold
# solution, and must not compute a reward.
# The execution gate stays the sole reward authority as harnesses are added.
# Semantic false-accept still requires labeled exploit trials.
