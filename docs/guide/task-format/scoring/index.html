How scoring works

A task is evaluated by executing tests after the proposed repair.

From patch to result

  1. The agent receives the task and produces a code patch.
  2. The evaluator applies the patch in the task environment.
  3. Trusted tests are restored and run with the task’s network restrictions.
  4. The result records the test outcome and any execution error.

How to interpret a pass

A passing result means the patch passed the protected tests in that environment. Changing the agent’s copy of a test cannot make it pass. Execution errors never earn a positive score.

Tests can still miss incorrect solutions. That failure rate has not yet been measured; see Scoring limits.

Inspect the result

Save and review the run record before aggregating results. Read a result explains what to check. Submissions require a separate operator evaluation before appearing in verified results.
