The false-accept check

Which boundary produced the score, and what that boundary does not certify.

The false_accept_check block

Every result record carries this block. It records which deterministic execution boundary produced the score.

gate: "harbor_protected_tests"
Scoring is the Harbor execution gate and nothing else.
reward_source
The reward is read from result.json with the same reader the admission gate uses (harbor_score.read_harbor_reward).

Why a patch cannot score itself

protected_tests_relaid_by_harbor: true
The trusted tests/ are re-laid from the task package after the patch, so a patch that edits tests only changes a discarded workspace.
model_is_judge: false
The model is the subject under test, never the judge.
model_patch_touched_tests
Flags whether the model’s diff touched any test-named path; informational, and it cannot affect the score.

What false_accept: 0 does not claim

false_accept: 0 is a compatibility field scoped by scope to replay integrity: no acceptance bypassed the protected test run. It does not by itself establish semantic verifier quality, and it does not estimate semantic verifier false-accept, which remains null pending an exploit corpus.

That covers claim bypass only; semantic verifier false-accept remains unmeasured.

Records aggregate into a quality card.
