Quickstart

terminal-daily-bench is a living, execution-graded coding-agent benchmark.

How a run is scored

The model sees the task instruction and produces a patch. Harbor re-lays a protected test suite the model never sees. The suite runs under a network cut; the reward is its outcome.

The reward is the test outcome, never a model’s opinion.

Requirements

Three pieces, and tdb quality is the exception that needs none of them: it needs neither Harbor nor a model.

Python ≥ 3.11
Needed by everything. The scoring core is pure stdlib; there are no runtime dependencies.
An apptainer/singularity host
Needed by tdb run and tdb oracle. Both invoke harbor run ... -e singularity, which executes each task’s SIF image.
An OpenAI-compatible endpoint
Needed by tdb run with a real model. tdb oracle needs no model.

Current availability

Our scored runs use a private, locally patched Harbor 0.13.1 fork. Stock upstream Harbor rejects this bundle’s singularity backend options, so a third party cannot currently run tdb run or tdb oracle end to end.

The task packages, tdb doctor, tdb quality and tdb publish remain usable without that fork. No publication date is promised.

Install

Either route installs the tdb console script (terminal_daily_bench.cli:main in pyproject.toml).

Configure the model endpoint

The model call goes to a generic OpenAI-compatible endpoint: OpenAI, OpenRouter, vLLM, LiteLLM, or a local server.

Requests go to <base>/chat/completions. There is no default key. If the upstream rejects max_tokens, the client automatically retries with max_completion_tokens.

Run tdb doctor first

It reports which of the pieces above your host is missing, before you spend a model call finding out.
