Read a result

Check the outcome of a run before comparing it with other results.

Find the result

Each evaluation writes a JSON result and prints it to the terminal. Use the output option to choose a file location.

What to check

Evaluation
Confirm the model, task, and agent configuration match the run you intended.
Outcome
Check whether the protected tests passed. A local result does not by itself establish a verified leaderboard entry.
Execution
Review the recorded command calls, tool calls, and any error. Keep the result file when reporting a problem.

Compare results

A task counts as solved when more than half its runs pass: at least two out of three. Scores and rankings use the share of tasks solved. Beside horizontal score bars, ± gives the sample standard deviation of accuracy across repeated runs on the same tasks. It describes run-to-run variation. Results without complete repeat records show their published score without an error bar.

Efficiency compares success with the mean number of command calls per attempt. Each call to the terminal counts once, including a call that submits several shell operations. Tool calls also include actions such as reading or editing a file. Both passing and failed attempts are included; missing counts are not treated as zero.

When a run fails

A missing patch, a patch that cannot be applied, or an execution error never earns a positive score. The local record includes the failure reason. In published analyses, an unavailable or unaccepted result is treated as missing, not as evidence that the model failed the task.
