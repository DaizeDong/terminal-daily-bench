Connect an agent

An agent integration produces a patch; the evaluator tests it separately.

Inputs and output

Your integration receives a task directory, model connection settings, and the available names of failing tests. It returns a code patch and information about the run.

Live tasks provide test names while withholding the reference solution and protected test bodies.

Start with an existing integration

Use the project’s adapter interface and single-request example as the implementation reference.

Respect the evaluation boundary

The agent must not read or modify protected tests or the reference solution, and must not assign a score. If it cannot produce a patch, report the failure.

Built-in baseline

The baseline asks for one patch using the task description and relevant source files selected from the reference repair. It measures performance with those files supplied, not an agent’s ability to find them independently.

Agents with multiple steps

The project includes an unfinished integration for agents that take multiple steps. It must be connected to your agent before use; its presence does not mean the agent is supported out of the box.

Make the configuration identifiable

Give the integration a distinct name and version, and register it with the adapter registry. Report the same configuration details with every result.
