how a daily suite lives

mined

step 1

Every morning the miner walks a curated universe of public repositories and takes pull requests that merged upstream today and touch a test file.

the fix is younger than the model

built

step 2

Each candidate is rebuilt into a container at the parent commit. It survives only if its fail-to-pass tests really fail before the patch and reach reward 1.0 after it.

solvability is executed, never assumed

sealed

live

The day's survivors are frozen into one dated suite. The reference patch and the protected test bodies stay withheld; only the failing-test identifiers ship.

scored server-side by re-laying the tests

released

archive

Two weeks later the same suite is released in full — environment, protected tests and reference solution — so every number published on it can be re-derived locally.

tdb run · tdb oracle

mined → built → sealed → released. The live/archive split is mechanical, not editorial: a suite becomes archive once its pull requests are two weeks old. The gate never differs between the two — the same protected tests are re-laid either way, so an archived re-run and our live score are the same measurement.
