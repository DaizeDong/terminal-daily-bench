axes are reported separately — the composite never hides an axis that has collapsed. a track filled in solid ink is at or above its threshold; a dimmed fill, marked ↓ on the value, is below it, and the notch on the track is the threshold itself. the interval on D is a seeded bootstrap, and at this task count it is wide on purpose.

how far from a claim

tasks we have vs tasks the interval needs

standard error scales as 1/√N, so the bootstrap SE at today's N extrapolates to the task count that would buy a research-grade interval. this is the number the daily pipeline is aimed at — a target, not a promise.

what each axis means

one sentence each

[0,1]

two further axes ship in the library but are not on this card, because they read task signatures and ordinal gate-states rather than the solve matrix: A angle coverage (build → partial → full-F2P → clean, each conditioned on reaching the previous stage) and R diversity (1 − the near-duplicate rate over {repo, files, f2p} signatures). both are advisory. see the methods note.

how to read these axes

what a bad value actually looks like

axis what it means what a bad value looks like
measured
D fraction of tasks that split the field — strictly between 0 and all models solving it. low D: the set is mostly all-pass or all-fail rows, which carry no information about who is better. below the min_D gate the day cannot rank anyone.

—
C normalized entropy of the per-task solve-rate buckets — does the set span easy to hard? C near 0: every task sits in one difficulty band, so the set measures a single point on the ability curve rather than a range.

—
M fraction of tasks with no strong ability inversion (a clearly weaker model passing what an abler one misses). M below 1 flags flaky, mislabeled or gameable tasks. but M is vacuously 1.0 when no model pair is clearly separated — a perfect M on a thin day is not an achievement.

—
I 2PL Fisher test-information — additive across tasks, and SE = 1/√I. information concentrated in one or two items: the rest of the suite is decorative, since an all-pass or all-fail task contributes almost none of it.

—
KR-20 internal-consistency reliability over binary items — do the tasks measure one coherent ability? below the conventional bar (min_kr20) the set is not yet one instrument; a negative KR-20 means items actively contradict each other.

—
A angle coverage: each of the four conditional capability angles needs enough cells to reach its conditioning stage. an angle whose conditioning population is under min_support is undefined — a set where nothing reaches full-F2P cannot measure "fixes it without breaking passing tests" at all.

advisory
R diversity: 1 − redundancy over {repo, changed files, F2P} signatures. low R: the day filled with near-clones of one PR family. two tasks in the same repo scoring above the similarity cut count as duplicates.

advisory

the small-N caveat, stated plainly

readiness advisory

the "measured" column is read from real gate-scored matrices of the current day. a handful of tasks is far too few to certify any of these numbers: D can only take a few discrete values, one task flipping moves it by a large step, and the bootstrap interval on D is correspondingly wide. read the column as the current reading of a thin day, not as a property of the benchmark.

why we do not claim more than this

the honest part

a ranking is not a result

at a handful of tasks per model, the Wilson interval on any single model's rate covers most of the other models. the order on the leaderboard is a reading of one day, not a finding.

D is coarse at small N

with few tasks, D can only take a few discrete values, and one task flipping moves it by a large step — which is exactly why the bootstrap interval is so wide.

not yet one instrument

under the conventional KR-20 rule of thumb, items below the bar are not yet demonstrably measuring a single coherent ability; treating the total score as a skill estimate would be overreach.

vacuous highs are not wins

M is 1.0 whenever there is no ability separation left to violate, so a perfect M on a thin day is the absence of evidence against the set, not evidence for it. we show the raw value rather than hiding it behind a composite.

required-N is an estimate

it assumes the next tasks are drawn like today's, and it comes from a bootstrap SE that is itself noisy at this size. read it as an order of magnitude.

what it is good for

catching a day whose set has quietly collapsed — every task all-pass or all-fail, an item correlating negatively with total score, a difficulty band entirely missing — before anyone reports a leaderboard from it. a defect detector with an explicit threshold, run every day.

the readiness verdict on this page is almost always not yet, and we publish it anyway. readiness is advisory only: it never gates an accept, never touches the reward path, and cannot promote or demote a task.
