archive vs live

archivelive

Archived tasks (≥ 2 weeks old) ship in full, gold patch included, so you can reproduce locally. Live tasks withhold the solution and the protected test bodies — submit the patch and it is scored on our side.

Each run writes one JSON record per (model, task) cell. solved is reward ≥ 0.999; any failure — no diff, patch does not apply, trial error, unparseable result — yields reward 0.0 with the cause in error. A crash never produces a positive score.

step 3 · the part that matters

pending → verified

Your number never enters the board. On ingest the entry is stored as pending with verified_reward = null. A node worker replays the patch through the execution gate; only then does the entry flip to verified and start contributing. Until it flips it is listed and counts as an attempt worth 0.

execution proof only

why a patch cannot cheat the score

The protected tests/ are re-laid by harbor after your patch is applied, from the trusted task package. A patch that edits tests only changes an agent-side workspace that is thrown away before scoring. Runtime egress is cut (--network=none), so a "fix" cannot phone home. The reward is byte-for-byte execution truth out of harbor's result.json — never a string a model emitted.

no model ever grades a model

integrity rules (enforced, not requested)

1. Scoring is execution-only; no scaffold ever scores.
2. Patches may not edit tests — the edit is discarded.
3. Runtime egress is cut; a submission that needs live network is rejected.
4. Live tasks are scored server-side, gold patch withheld.

step 5 · terminal_daily_bench/adapters/base.py

adding a scaffold: the HarnessAdapter contract

The contract is deliberately narrow: input = (task dir, failing test ids, model id/endpoint), output = (unified diff, telemetry). An adapter produces a candidate patch and must not score. Keeping scoring out of the adapter is exactly what keeps false_accept = 0 as harnesses are added.

rules produce_patch must obey

MUST NOT read or write the protected tests or the gold solution. MUST NOT compute a reward. A harness failure returns an AdapterResult with error set and an empty patch — a 0-reward attempt, not a crash.
