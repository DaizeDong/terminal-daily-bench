endpoint agnostic

OpenAI, OpenRouter, vLLM, LiteLLM or a local server — anything that speaks the OpenAI wire format. The model id oracle replays the task's own solution/oracle.patch and needs no key at all.

OPENAI_BASE_URL · OPENAI_API_KEY

where scoring happens

Harbor applies your patch inside the task container, then re-lays the protected tests/ from the trusted package and runs them under a network cut. Paths: TDB_SIF_CACHE, TDB_OVERLAY_DIR, TDB_WORK.

apptainer / singularity required

archive vs live

Archived tasks (≥ 2 weeks old) ship in full, gold patch included, so you can reproduce locally. Live tasks withhold the solution and the protected test bodies — submit the patch and it is scored on our side.

archive live

Each run writes one JSON record per (model, task) cell. solved is reward >= 0.999; any failure — no diff, patch does not apply, trial error, unparseable result — yields reward 0.0 with the cause in error. A crash never produces a positive score.

content-addressed id

record hashes the six required fields (sha256, first 16 hex chars) into id. That gives dedup and tamper-evidence: change any required field and it is a different submission.

3 — pending → verified

the part that matters false_accept 0

Your number never enters the board. On ingest the entry is stored with pending and verified_reward = null. A node worker replays the patch through the execution gate; only then does the entry flip to verified and start contributing. Until it flips it is listed and counts as an attempt worth 0.

why a patch cannot cheat the score

The protected tests/ are re-laid by harbor after your patch is applied, from the trusted task package. A patch that edits tests only changes an agent-side workspace that is thrown away before scoring. Runtime egress is cut (--network=none), so a "fix" cannot phone home. The reward is byte-for-byte execution truth out of harbor's result.json — never a string a model emitted.

no model ever grades a model

integrity rules (enforced, not requested)

1. Scoring is execution-only; no scaffold ever scores.
2. Patches may not edit tests — the edit is discarded.
3. Runtime egress is cut; a submission that needs live network is rejected.
4. Live tasks are scored server-side, gold patch withheld.

5 — adding a scaffold: the HarnessAdapter contract

terminal_daily_bench/adapters/base.py

The contract is deliberately narrow: input = (task dir, failing test ids, model id/endpoint), output = (unified diff, telemetry). An adapter produces a candidate patch and must not score. Keeping scoring out of the adapter is exactly what keeps false_accept = 0 as harnesses are added.

@dataclass
class AdapterResult:
    patch: str                                               # unified diff the harness produced
    telemetry: Dict[str, Any] = field(default_factory=dict)  # tokens, cost_usd, turns, wall_s
    error: Optional[str] = None

class HarnessAdapter(abc.ABC):
    name: str = "base"

    @abc.abstractmethod
    def produce_patch(self, task_dir: str, failing_test_ids: List[str],
                      model: str, **kwargs: Any) -> AdapterResult:
        ...

rules produce_patch must obey

MUST NOT read or write the protected tests or the gold solution. MUST NOT compute a reward. A harness failure returns an AdapterResult with error set and an empty patch — a 0-reward attempt, not a crash.

from the base-class docstring

reference implementation

adapters/single_shot.py loads the task, finds the files the reference solution touches, reads them out of the SIF for context, builds a strict one-diff prompt, calls the model, extracts the diff, returns telemetry. No scoring anywhere.

SingleShotAdapter · name = "single_shot"

multi-turn agents

adapters/terminus.py is a stub marking where to wire terminus-2, Claude Code, Aider, OpenHands or SWE-agent. Any harness that accepts a custom OpenAI base URL drives an arbitrary model unchanged.

TerminusAdapter · name = "terminus"

registering it

# terminal_daily_bench/adapters/__init__.py
REGISTRY = {a.name: a for a in (SingleShotAdapter, TerminusAdapter, YourAdapter)}

Add your class to that tuple (and to __all__) with a unique name, then set the scaffold field of your submission records to that name — the board groups runs by (submitter, model, scaffold).

The failing test IDs you pass as failing_test_ids are the fail_to_pass selectors in each task's record.json. Live tasks ship those selectors but withhold solution/ and the protected test_outputs.py body. full docs →
